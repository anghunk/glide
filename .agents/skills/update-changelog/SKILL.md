# 更新版本日志

以 `mygo.json.version` 为唯一版本来源，将当前版本的完整变化整理为中文更新日志。日志路径取 `mygo.json.updates.changelog`，未配置时使用项目根目录的 `CHANGELOG.md`；相对路径以项目根目录解析。

## 确定版本与修改范围

- 从项目根目录读取配置、日志和 `git status --short`，保留已有工作区改动。
- 当前版本已经有标题：在该版本区块内核对、补充、合并和精简条目，不重复创建标题，不只追加最近一次提交。
- 当前版本没有标题：在较旧版本之前新增当前版本区块，保留文件总标题、前言和其他版本内容。日志不存在时创建 `# Changelog` 及当前版本区块。
- 版本标题必须严格为 `## <version>`，例如 `## 0.1.2`。项目发布脚本 `scripts/release.py` 按此格式提取日志，不能添加 `v`、方括号、日期或分类后缀。
- 当前版本标题重复、配置版本无效或版本顺序出现无法判断的冲突时，说明具体问题并询问，不猜测修复、不自动升降版本。

## 收集当前版本的证据

目标是“上一版本结束后至当前工作区”的完整变化，不能把当前版本标签或最后一次修改日志的提交直接当作起点。

1. 查看版本标签、相关提交及 `mygo.json` 的版本历史。优先选择当前分支祖先中、版本低于当前版本的最近发布标签作为基线；标签前缀取 `updates.tagPrefix`，未配置时用 `v`。按 SemVer 比较版本，不能按字符串或标签创建时间判断大小。
2. 若找不到可靠的上一版本标签，查看 `git log --first-parent -p -- mygo.json`，找到进入当前版本的版本变更提交，以其父提交作为候选基线，并结合旧日志核对。首次版本可从仓库起点整理；其他情况无法可靠确定边界时，先完成可独立核实的检查，再询问用户基线，不把全部历史算入当前版本。
3. 基线确定后，读取 `git log <base>..HEAD`、`git diff --stat <base> HEAD` 及相关实际 diff，检查关键实现确认最终行为。提交标题只作为线索，不能直接逐条复制；一个提交可能包含多种类型。
4. 补充检查暂存区、未暂存和相关未跟踪源码文件。`git diff HEAD` 可检查已跟踪文件的工作区净变化，未跟踪文件需单独读取；跳过密钥、构建产物和缓存。对照基线与最终工作区核实，排除已回退、被替代或尚未实现的内容。
5. 与当前版本已有日志逐项核对。保留人工补充且未被证据否定的有效说明；没有本次新增 diff 不代表旧条目无效。无法证实或否定的既有说明先保留并在结果中指出，不擅自删除。较旧版本的条目不能重复算作当前版本的新功能。

例如：配置为 `0.1.2`，已有 `v0.1.1` 和 `v0.1.2` 标签时，以可达的 `v0.1.1` 为基线，检查其后提交及工作区；即使 `HEAD` 正好是 `v0.1.2`，也不能据此判断当前版本没有变化。

## 分类与措辞

使用 Markdown 无序列表，每条以小写类型标记开头，采用 `- <type>: <简短中文说明>`。不创建空分类，不添加分类二级标题。

| 标记 | 使用范围 |
| --- | --- |
| `feat` | 新增用户可用的功能或能力 |
| `fix` | 修复错误行为、失败或兼容性问题 |
| `perf` | 已实现的性能、资源占用或响应速度改善 |
| `refactor` | 值得记录、但不改变外部行为的结构调整 |
| `docs` | 值得记录的文档变化 |
| `build` / `ci` | 构建、打包、发布流程或持续集成变化 |
| `chore` / `test` / `style` | 确有必要披露且不属于上述类型的维护、测试或纯格式变化 |

- 以实际效果决定分类，提交前缀与代码不一致时以代码为准。行为或交互改善按其实际作用归入新增或修复，避免把所有“优化”都写为 `perf`。
- 每条尽量一句话，突出“改了什么、带来什么结果”；同一功能的多次提交合并，不同类型的独立变化拆开。优先排列 `feat`、`fix`、`perf`，再列其他实际存在的类型。
- 保留影响使用的限制、迁移步骤、默认值或平台差异；不要复制实现细节、提交哈希、文件清单，也不要使用“全面优化”“体验升级”等无法核实的泛化描述。
- 纯版本号调整、更新日志自身变化、重复合并提交和无实际价值的琐碎维护不必单列。存在破坏性变化时，在对应条目中明确标注 `BREAKING CHANGE` 并简述影响。

格式示例（只示范结构，内容必须来自真实证据）：

```markdown
## 0.1.2

- feat: 新增智能互译，自动在中文与英文之间切换目标语言。
- fix: 修复 macOS 更新应用后取词权限失效的问题。
- build: 统一开发与发布签名身份，缺少证书时停止构建。
```

## 写入与验证

- 只修改目标日志的当前版本区块；需要创建文件时补齐总标题。保留其他版本和用户无关改动，不修改配置版本、代码、Git 分支、标签或提交。
- 重复执行时核对已有条目并去重；相同证据应产生稳定内容，没有变化就不强行改写，不新增“无更新”占位条目。新版本没有任何可证实变化时不创建空区块，说明原因。
- 写入后检查 diff，确认当前版本标题恰好一个、区块非空、条目带分类且没有重复，其他版本内容未改动。不为日志修改运行应用构建或新增测试文件。
- 回复说明目标文件、版本、是更新现有区块还是新增区块，并简述基线和必要的不确定性。用户仅要求预览时展示草稿，不写入文件。
